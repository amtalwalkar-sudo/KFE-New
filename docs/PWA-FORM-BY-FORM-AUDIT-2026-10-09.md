## Audit method and confidence

- **Active** means reachable from the current router and its imported view/component graph, based on the source paths inspected.
- **Persistence path confirmed** means the UI calls an application/service/store path whose repository and canonical store are identifiable in source.
- **Consumer path** names the read-model or calculation service currently consuming the canonical store; it does not assert every business scenario has runtime-tested end-to-end.
- **Confirmed gap** is directly visible in source. **Test required** means the source reveals a race or behavior that must be proven by a regression test before calling it a defect.
- No business fields are proposed beyond the frozen inventory. This is an audit, not authorization to redesign or remove fields.

## 2. Persistence and authority trace

### Admin source records

`AdminSourceForm` → `AdminView` / `CalculationsView` / `FirstRunSetupView` → `AdminService.save` → `validateAdminForm` → `AdminRepository.save` → canonical IndexedDB store + mutation/audit path. The repository additionally enforces relationships, payment/source integrity, and immutable loan contractual fields. `PerformanceRepository.getSnapshot` reads the authoritative stores; `PerformanceService` and domain calculation services consume that snapshot. Components must not write directly to IndexedDB.

### Work shift/trip lifecycle

`WorkContextForm` / swipe → `WorkModuleView` handler → Pinia `useShiftTripStore` → `WorkService` → `ShiftTripRepository` → canonical `shifts`/`trips` with mutation/audit. Shift total revenue is authoritative. Trip fare/revenue and cancellation amount are supporting detail only. GPS enrichment runs after the authoritative lifecycle transition and must not hold the swipe commit.

### Work and Calculations fuel capture

Work or Calculations → `WorkService.recordFuel` / `CalculationsService.recordFuelBaseline` → `FuelRepository.create` → `fuel_logs` with pending mutation/audit. Fuel quantity is derived from amount ÷ price/kg and validated against the persisted quantity. Timeline edit uses fuel store → WorkService → FuelRepository update; Timeline delete uses the corresponding service/repository removal path.

### Timeline correction path

Timeline trip edit → `WorkService.updateTrip` → `ShiftTripRepository`; Timeline fuel edit/delete → fuel Pinia store → `WorkService` → `FuelRepository`. These are corrections to existing authoritative records, not separate display-only changes. Tests must prove that historical/audit and downstream calculations remain consistent after correction/deletion.

### Read-model consumers

- `PerformanceRepository` snapshots shifts, trips, fuel logs, vehicles, drivers, compliance, maintenance, loans, loan payments, prepayments, driver targets, break-even inputs, settlements and Business Setup settings.
- `PerformanceService`/domain performance and finance engines derive actual P/L, provisions, targets, loan position and supporting breakdowns from those records.
- `TimelineService` reads canonical operational records; Timeline is a read/correction surface, not a second authority for shift revenue.
- Work reads active lifecycle state and target snapshots; it must not derive a separate revenue authority from trip fare fields.

## 6. Regression-first baseline and remediation history

The regression-first test was run against the implementation before the fixes. After correcting a syntax error in the test harness, CI reported four distinct failures:

- Admin source forms had no stable draft identity or shared draft-service integration.
- Admin parent save handlers had no explicit committed-draft clearing boundary.
- Timeline trip/fuel editors had no shared draft persistence/restore path.
- Work draft writes were fire-and-forget, with no serialized write/clear queue.

Those were source-contract findings, not merely UI impressions. The subsequent implementation added a shared FormDraftService that serializes saves and clears; parent/workflow-scoped identities and restoration for Admin/first-run/Calculations forms; record-scoped Timeline trip/fuel recovery; and serialized Work draft writes with commit-time guards and surfaced clear errors.

The targeted contracts passed after the changes, and current main CI run #3282 passed the full contract/build/deployment/emulator gates. The prior failures are kept here as regression history rather than represented as current failures.
